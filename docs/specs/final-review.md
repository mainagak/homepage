## 判定: リリース可

MVPとしての初回リリース(フェーズ1〜8のゲート)はすべて所定の基準(承認/合格)を
文書上・実ファイル上の両方で満たしていることを確認した。フェーズ7・8で発見された
2件の重大バグ(`contact.cgi`のUTF-8文字化け、`contact.html`のスクリプト競合)は、
いずれも自己申告を鵜呑みにせず独立した視点で再検証され、実際にバグを検出できる
テストで裏取りされた上で解消が確認されている。ドキュメント間で見落とし・
握りつぶしにあたる項目も見当たらなかった。

**残存する課題はすべて、(a) 運営者本人の実世界での作業(Vercelアカウント作成、
reCAPTCHA登録、実ロゴ・実GA4測定IDの提供、Cyberhome実契約情報の確認、GitHub
Secrets/Variables登録、FTPでの`.htpasswd`等の配置)を要するもの、または
(b) 意図的にPhase 10(保守サイクル)へ繰り越すと合意済みの機能(FAQ管理GUI等)、
のいずれかに分類でき、エージェント側の追加作業(コード修正・再テスト)を要する
ブロッカーは存在しない。**

### リリース前に運営者(人間)が行う必要がある作業(パイプラインの未完了ではない)

1. Vercelへの実デプロイ(アカウント作成含む)を行い、実URLを`VERCEL_API_BASE_URL`
   (`site/js/chat-widget.js`・`contact-form.js`)に反映する。
2. Google reCAPTCHA v2を`jyoho1.web.cyberhome.ne.jp`ドメインで登録し、サイトキーを
   `site/contact.html`の`data-sitekey`に、シークレットキーをVercelの環境変数
   `RECAPTCHA_SECRET_KEY`に設定する。
3. GA4の実測定IDを取得し、全8ページ+`templates/header.html`の`G-XXXXXXXXXX`を
   置換する。
4. 実ロゴ画像アセットを入手し、`site/images/logo-placeholder.svg`を差し替える。
5. Cyberhomeの実契約情報(正確な月額費用、Apacheバージョン・文字コード、
   `AuthUserFile`絶対パス)を確認し、必要なら`.htaccess`を初回デプロイ時に調整する。
6. GitHub Secrets/Variables(`CYBERHOME_FTP_HOST`/`_USER`/`_PASSWORD`/`_PORT`/
   `CYBERHOME_PUBLIC_HTML_PATH`、`SITE_BASE_URL`、`VERCEL_API_BASE_URL`、
   `SMOKE_TEST_SECRET`等)をリポジトリに登録する。
7. `.htpasswd`(dl/qr用)・`site/conf/hmac_secret.txt`の実ファイルをFTPSで配置する
   (`.example`のみコミット済み、Vercel側の`INTEGRATION_HMAC_SECRET`環境変数と
   同じ値にすること)。
8. 設立年「2030年」の対外表記について、事業判断として最終確認する(コードは
   指示通り正確に反映済み、事実誤りではなく本当に対外公開してよいかの確認)。
